应用没有自建后端，也没有 Swift 包外部依赖。Codex CLI 是用户单独安装的运行依赖。

界面优先用布局、分组和控件状态解释功能，避免不必要的辅助标签和说明。账号与反馈固定在头部，额度及卡片在中部滚动；重复解释移至悬停帮助，消费风险和异常恢复仍明确展示。浮层适配所在屏幕的可用高度，独立窗口可调整大小。重置结果与后续读取结果分别呈现，读取失败不覆盖已经确认的操作结果。

`UsageMonitor` 支持注入客户端和偏好存储；默认仍使用独立 Runtime 与系统应用偏好。离线编排测试使用临时目录、本地假进程和独立 UserDefaults suite，验证预检与重试流程，不接触真实账号。

状态栏使用单个 `NSStatusItem`：左键打开承载 SwiftUI 面板的 `NSPopover`（由应用管理收起，避免系统 transient 行为与菜单跟踪竞争；Escape 可关闭），右键或 Control 点按打开原生设置菜单。面板显示期间临时观察应用内外的鼠标点击及实际的应用切换，补足菜单关闭后的自动收起；菜单临时接管焦点、菜单跟踪和面板内的子窗口交互不会触发额外关闭，外部点击使用事件携带的屏幕坐标；菜单期间的外部交互由 `PopoverDismissalState` 暂存，最后一个菜单关闭后处理。面板关闭或应用退出时移除观察器并清空待关闭状态。不监听全局键盘或拦截鼠标事件；只在本应用面板内处理 Escape 关闭，菜单和子弹窗保留各自的取消行为。用量与时钟变化通过 Observation 更新标签，偏好修改通过 UserDefaults 通知即时更新；退出时释放监听和状态栏入口。

确认页以不可变的 `ResetConfirmation` 绑定账号键、卡片 ID、原重试键及显示的额度窗口。页面和执行层使用同一确认对象校验，刷新不能将新操作切换为另一笔重试；预检后再次匹配确认对象。新操作通过文件锁内的 `prepareNew` 仅创建新记录，若已有待确认记录则要求重新确认，不自动采用其键。

## 启动与刷新

启动 CLI 子进程 → `initialize` → `initialized` → `account/read` → `account/rateLimits/read`。

浏览器登录调用 `account/login/start`，只打开受支持的官方 HTTPS 主机链接，回调由 CLI 负责。账号通知会触发防抖刷新；进程退出或请求超时会关闭传输，下一次刷新重建。

服务器使用多桶结构时优先解析该结构，避免重复展示历史单桶字段。缺失值保留未知状态，不能当作零用量或没有重置卡。失败时保留旧数据并在面板标记。

## 手动重置

1. 用户选择卡片，展示账号、当前窗口用量、数据更新时间、完整到期时间和不可撤销提示。
2. 用户明确确认；数据失效或卡片不可用时禁用新的重置。
3. 再读取账号和卡片，核对账号身份以及所选卡片，阻止使用过期快照。
4. 新操作在文件锁内仅创建自己的待确认记录，原子写入卡片 ID 与 UUID；已有任何未决操作时拒绝创建。重试必须继续匹配原账号、卡片和幂等键。
5. 调用 `account/rateLimitResetCredit/consume`。同一次操作的所有重试复用幂等键。
6. 明确结果后仅清除匹配该键的本地操作，再读取用量。迟到的旧结果不能清掉更新的记录。

超时、断线、存储损坏、未知服务端结果均不能自动产生新的请求标识；临期自动重试只能复用已持久化的原请求。文件锁仅保护本机记录；服务器幂等语义仍是防止重复消耗的最终保障。

## 临期处理

默认关闭，配置以当前账号键绑定。应用每 30 秒及唤醒时检查；每次先刷新账号与用量，再选取进入 15 分钟范围且未处理的最早到期卡片。未知到期时间、已过期、不可用卡片、读取失败和非自动创建的未决重置均停止处理，不依赖当前用量大于零。

提醒模式通过注入的通知适配器提交本地通知，点击只导航到确认页；自动模式生成固定目标并复用重置预检，在发送前再次验证配置与账号。通知权限只在用户启用提醒时请求，测试使用假适配器。自动授权使用固定账号的 `AutomaticExpiryAuthorization`；取得文件锁并预留次数后，在消费 RPC 前重新核对当前时间及配置。通知导航由 `CreditExpiryReviewQueue` 暂存，刷新或 sheet 关闭期间不丢弃意图。

`expiry-actions.json` 在文件锁内原子认领账号/卡片/模式标识；自动认领在消费请求前落盘，认领后不自动释放，防止为同一卡片创建新请求。`pending-resets.json` 的可选自动元数据保存原到期时间、次数、最早重试时间与租约；最多 3 次自动尝试始终复用同一账号、卡片和幂等键。文件锁内先预留次数及 90 秒租约再发送 RPC，完成后间隔至少 30 秒才可重试；进程崩溃则待租约过期恢复，同一次数的迟到回调不能释放后续尝试的租约。次数在发送前计入，崩溃时可能少发一次，优先避免超额请求。模式切换不重置记录；发送失败的提醒可释放重试。卡片或原到期时间变化、过期、预算耗尽时保留原请求供人工核实；旧版无自动元数据的待确认请求不自动接管。

## 满额自动 hello

默认关闭，配置绑定账号稳定 ID 与一个 `codex` 额度窗口；默认选择较短窗口，不依赖 7 天额度存在。与临期处理共用 30 秒检查和唤醒入口，未启用时不创建模型会话。处理与手动重置、刷新共用主线程忙状态；有未决重置时暂停。

先刷新账号和额度；只有原始 `usedPercent == 0` 且 `resetsAt` 是有效时间戳时才准备发送，过去或未来的重置时间都可接受。独立进程验证账号后发现默认文本模型、建立临时会话，再次读取账号和额度，最后在文件锁内认领并落盘。消费请求前重新核对配置。`turn/start` 的确认不代表完成，必须收到匹配线程和回合的 `turn/completed` 且状态为 `completed`。

持续满额时，重置时间变化不会创建新事件。`automatic-hello.json` 保存已认领状态与发送后的用量基线；后续额外使用至少 1 个百分点后重新准备，恢复满额时可认领下一次。早于新记录的迟到快照、旧请求回调均不能重开新认领。网络结果未知也不重试；崩溃后的首次有效非零读数成为保守基线。关闭再开启不清空记录。

问候进程使用同一 CLI 独立账号配置，采用空工作目录、关闭 hooks/应用/插件/MCP/命令等能力，并设置限制读取范围的只读沙盒和最小指令。模型回复不进入应用状态或日志。真实服务端计时行为未验收，不以客户端推算替代服务器返回值。

## 格式与安全

额度计算只处理数字和时间戳；本地化仅作用于显示。日期模板使用系统日历顺序、时区和 `j` 小时制，不写死北京时间或 24 小时。

子进程只继承运行、证书和代理相关环境变量，避免 IDE 或终端的 API 密钥覆盖独立登录配置。进程标准错误被丢弃，错误界面不显示原始 JSON-RPC 错误详情。

## 外观

`appearance` 本地偏好在所有面板间共享，支持跟随系统、亮色、暗色。外观由 AppKit 的 `NSApplication.appearance` 统一控制；手动模式设为 Aqua / Dark Aqua，跟随系统时清除应用和窗口覆盖并继承系统动态外观，避免 `preferredColorScheme(nil)` 留下旧状态。颜色由 `AppPalette` 按语义统一提供，不修改 macOS 全局外观。状态栏模板图继续跟随系统菜单栏的明暗，不被面板主题覆盖。
