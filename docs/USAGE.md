# 使用指南

[返回 README](../README.md)

## 登录与刷新

启动后点击「使用 ChatGPT 连接」，在官方浏览器页面登录。应用独立保存登录状态，不直接复用其他 Codex 客户端的配置。

默认每 5 分钟读取用量；打开面板、系统唤醒及账号变更也会刷新，可点击面板右上角手动刷新。实际用量来自最近一次成功读取，并非秒级实时数据。

默认查看 Codex 中最长的额度窗口；服务器提供多个窗口时，顶部摘要同时显示各窗口的已用额度，点击可切换详情。套餐、额度窗口及重置卡字段由服务端决定，缺失信息不视为零。

连接或读取失败会在顶部显示恢复入口。「重新读取」只刷新账号与额度，不使用重置卡。找不到 CLI 时，可直接选择可执行文件或查看安装帮助。

## 用量与时间基准

```text
周期起点（推算） = 下次重置时间 − 窗口长度
参考进度 = 已过去的周期时间 / 窗口长度 × 100%
偏移 = 实际用量 − 参考进度
```

例如实际用量 35%、参考进度 28%，面板显示 **消耗超前 7 个百分点**。状态栏保留有符号偏移，正值表示消耗超前，负值表示滞后；自然时间包含睡眠和休息时间。

一般偏移使用正文色，超前超过 10 个百分点时使用琥珀提醒色，未知值使用灰色。这只是显示规则，不代表预测额度耗尽，也不改变重置卡处理策略。

窗口起点由服务器返回值推算，不是明确提供的历史起点。手动重置若保留原窗口终点，基准仍按原窗口计算。缺失窗口长度或已到重置时间时，不推算偏移。

读取失败、超过 10 分钟未更新或当前周期已结束时，面板、状态栏和设置预览停止展示偏移；保留最后读取的用量及仍可计算的参考进度，刷新成功后恢复。面板底栏显示更新时间。

## 状态栏与外观

左键点击状态栏打开用量面板，右键或 Control 点按打开设置菜单；面板底栏齿轮提供相同入口。

独立窗口可以调整大小，菜单栏面板根据屏幕可用高度显示并支持滚动；账号、错误恢复入口和底栏保持可见。刷新期间仍可调整外观、隐藏邮箱和状态栏显示，账号退出及 CLI 切换等待请求结束。

「状态栏显示…」可以选择仪表盘、用量图表、闪电、圆环或无图标，并独立开关已用百分比、参考进度和偏移。启用的文本按此顺序排列，偏移单位 `pp` 表示百分点。数值对应当前选择的额度窗口，至少保留图标或一项文本。

<img src="images/menu-bar-settings.png" alt="状态栏显示配置，使用虚构演示数据" width="380">

设置实时预览并自动保存。外观支持亮色、暗色和跟随系统；菜单栏图标跟随系统菜单栏背景。日期、时区、12/24 小时制和数字使用系统格式，界面目前主要为简体中文。

「隐藏邮箱」位于齿轮和状态栏右键菜单。开启后遮盖邮箱，确认页显示「已隐藏」，辅助功能及悬停提示不读出邮箱原值；其余数据与操作照常显示。

## 登录时启动

在齿轮菜单或状态栏右键菜单中开启「登录时启动」，下次登录 macOS 时会在状态栏运行，不自动弹出主面板。手动打开应用仍显示面板。

该选项使用 macOS 登录项管理，读取系统实际状态。若显示「待系统允许」，选择「在系统设置中允许…」完成授权；取消勾选可撤销待允许的请求。在系统设置中修改后，切回应用或重新打开右键菜单即可同步。

请将正确签名的应用放在固定位置（建议“应用程序”文件夹）后开启。无签名的源码构建可能被系统拒绝注册，应用会显示错误，不会把失败显示为已开启。

## 重置卡

数量以服务端返回值为准，详情列表可能少于总数。未提供到期时间不代表永久有效。临期标签按本地日期区分：红色「今日到期」、琥珀色「明日到期」，其余三天内到期显示中性灰「三天内」。只有标签着色，卡片行保持统一背景。已过期或超过三天的卡片不显示临期标签。

点击「使用」只打开确认页，展示账号、当前用量、更新时间和卡片到期时间。确认页不会通过回车键直接提交。

<img src="images/reset-confirmation.png" alt="重置确认页，虚构数据及无操作按钮" width="370">

手动操作确认「消耗 1 张并重置」后才会发送写请求，且无法撤销。实际重置范围由服务器决定，可能包含其他额度窗口。真实重置操作尚未验收。

确认页绑定打开时的账号、卡片及原重试标识；后台操作变化时会禁止提交，需取消后重新打开。新操作发送前再次核实账号及卡片，并持久化请求标识。

收到明确重置结果后，即使最新额度读取失败，也会保留该操作的结果；此时使用顶部「重新读取」刷新即可。没有发生重置和卡片不可用分别显示为说明或警告，不使用成功标记。

### 到期前 15 分钟处理

此功能从 `v0.2.3` 开始提供；`v0.2.1` 及更早安装包不包含此配置。

在齿轮菜单或状态栏右键菜单选择「重置卡临期处理…」。默认关闭，可先选择处理方式再开启：

也可点击重置卡标题旁的铃铛或自动处理图标打开设置。开启后，卡片区显示当前模式、暂停或待核实状态；符合自动重试条件时显示已尝试次数及最早重试时间，实际发送仍以账号、卡片和服务端预检为准。

- **提醒后人工确认**：需要允许系统通知。卡片进入到期前 15 分钟范围后发送通知；点击「查看并确认」打开原有二次确认页，不直接使用卡片。通知正文不包含邮箱。
- **自动使用**：启用时需要确认授权；授权固定弹窗打开时的账号，账号变化后需重新确认。卡片临期后直接尝试使用，**已用额度为 0% 时也会尝试**；服务端决定实际消费与重置结果。需要服务端提供稳定的账号标识。

<img src="images/credit-expiry-reminder.png" alt="重置卡临期处理的提醒模式，虚构演示数据" width="380">

设置绑定启用时的账号，当前账号不匹配时暂停；为其他账号启用需先关闭再开启。多张卡按到期时间排序，每次检查最多处理一张；每张卡的请求标识和自动尝试次数持久化，重启或多实例共用最多 3 次的限额。提醒每张卡成功提交一次，系统专注模式、通知设置可能影响实际展示；发送失败可在后续检查重试。

仅在应用运行、Mac 唤醒且能读取账号时执行，每 30 秒检查并刷新服务端状态，可能有约 30 秒加网络延迟的偏差。休眠或退出期间不执行；唤醒后补查尚未到期且已进入 15 分钟范围的卡片，不补用过期卡。临期功能关闭时仍按默认 5 分钟刷新。

自动使用会重新核对账号、原到期时间及可用状态。异常或结果未知时，间隔至少 30 秒重试同一张卡，首次加重试总计最多 3 次；始终使用同一账号、卡片 ID、原到期时间和幂等键，不会改用其他日期的卡片。收到明确结果即停止，不为重复消费凑足次数。账号不匹配、卡片消失或到期时间变化、卡片已过期时停止自动重试；3 次仍未确认则保留原请求供人工核实，期间不自动使用其他卡片。旧版本或手动创建的待确认请求不会被接管为自动重试。**自动使用会消耗重置卡且无法撤销。**

### 超时与重试

超时不代表失败。「重试上次重置」会复用原请求标识并重发原写操作；若此前尚未完成，可能消耗 1 张卡，并非只读查询。

不要删除本地待确认记录，也不要把未知结果改成全新请求。同一幂等键用于避免重复消费，但实际服务端行为仍依赖官方接口。开发测试仅使用隔离的假服务，不消费真实卡片。

## 满额自动 hello

在齿轮菜单或状态栏右键菜单选择「满额自动 hello…」。默认关闭；选择额度窗口后开启，需要确认会消耗模型额度。设置绑定当时的账号与窗口，当前已经满额时也会尝试。默认选择较短的 Codex 窗口，不要求账号有 7 天额度；更换目标需先关闭。

每 30 秒、打开面板和唤醒后检查；仅在应用运行且 Mac 唤醒时生效。使用服务端原始已用值精确为 0 和有效的下次重置时间判断，不使用界面四舍五入的 100%。重置时间在过去或未来都可以触发，覆盖自然及非自然恢复满额。时间缺失、账号不匹配、读取失败或已有待确认重置时暂停。

每次满额只尝试一次，记录在发送前保存，刷新、重启、多实例、关闭再开启均不会重复发送。持续满额时，即使 hello 导致重置时间变化也不重发。为避免 hello 自身的微小用量导致循环，发送后以最新用量为基线，额外使用至少 1 个百分点、再恢复满额后才准备下一次；未知结果后的首次有效非零读数作为保守基线。

hello 在独立后台运行，准备和等待回复期间仍可刷新额度。登录、退出、切换 CLI、手动重置或临期自动重置会优先中断旧 hello；已发出的请求可能已经消耗额度，中断不撤销消费，也不会补发原请求。

请求失败、超时、断线或应用退出后不自动补发，也不使用 API 密钥兜底。CLI 返回的默认文本模型用于一次独立临时问候，不附带项目或已有聊天。设置页的「hello 已完成」仅表示模型请求完成，是否启动新的额度倒计时仍以服务端后续返回的数据为准；真实计时效果尚未验收。

## 常见问题

- **找不到 CLI**：默认查找 `/opt/homebrew/bin/codex` 或 `/usr/local/bin/codex`；可从齿轮菜单选择可信的可执行文件。
- **没有 Dock 图标**：这是菜单栏工具，可从状态栏进入面板。
- **没有重置卡或详情不全**：取决于套餐及服务器返回的字段，不能据此判断所有账号都支持该功能。
- **偏移显示「待更新」**：先手动刷新；缺失窗口长度或周期已结束时，需要等待服务端提供有效数据。

更多凭证与本地数据说明见 [安全与隐私](../SECURITY.md)。

## 检查更新

应用运行时每 24 小时最多自动查询一次 GitHub 最新正式版，检查时间跨重启保留。设置菜单提供「检查更新…」；发现新版后显示「新版本 X.Y.Z…」，点击打开本仓库对应的 GitHub Release 页面，由用户下载并替换应用。自动检查不会弹窗，失败时也不影响额度读取和重置操作。

更新检查不需要 GitHub 登录，只请求公开版本信息，不发送 ChatGPT 账号或额度数据。GitHub 不可访问时可稍后手动重试；遭遇限流时等待服务端指定时间再试。只提供正式版提示，不下载、安装、重启应用或升级 Codex CLI。

## 剩余额度趋势

默认面板保留进度条、参考进度和消耗偏移。进度条整行是点击热区，悬停时显示淡色圆角矩形并提示「点击查看趋势」；点击可原位切换至「额度趋势」，点击右上角「返回进度」恢复原视图；也可用 Tab 聚焦按钮后按空格切换。重新打开浮层或已关闭的独立窗口时恢复默认进度视图。鼠标点击后不会自动聚焦替代按钮；悬停显示淡色背景，键盘聚焦显示柔和细描边。切换仅改变展示，历史采样持续进行。

「剩余额度趋势」以剩余额度百分比为纵轴（100% 至 0%）。实线与小圆点表示成功读取的历史数据，虚线根据最近一小时的消耗趋势预测，竖线标注当前时间及本次重置时间。标题与返回入口共用一行，计算口径和采样条件可通过悬停查看。面板常驻显示重置倒计时，悬停可查看完整日期。预计提前耗尽时显示距耗尽的时间及比重置提前的时长，否则提示预计可用到重置。预测不代表精确剩余 token 数，也不发起模型调用。

沿用现有刷新频率：通常每 5 分钟采样；开启自动功能时相应的 30 秒刷新也会记录。每个窗口按固定的 30 秒时间片合并连续采样，时间片内额度变化会更新最新采样点，不会丢弃最新读数。至少积累 3 个采样点、跨度达到 10 分钟后才预测；最近无消耗时不推算耗尽时间。算法采用最近一小时的线性回归，包含这段时间内的闲置，假设接下来维持近期平均使用强度。淡色范围是已观测到的不同消耗速度对应的情景范围，并非统计置信区间或准确率保证。

采样超过 15 分钟中断、剩余额度回升或重置时间变化时开始新分段，不跨段推算。数据失效或读取失败时暂停预测，历史采样仍保留。关闭应用期间不采样，恢复运行后不能补出离线期间的曲线。

历史仅保存在本机 `~/Library/Application Support/CodexWatcher/State/usage-trend-<账号哈希>.json`，按账号和窗口隔离；每次成功采样时清理该账号 8 天前的数据，每窗口最多保留 4096 点。退出登录会清除界面中的历史，但保留本地文件以供下次连接恢复；可在关闭应用后删除 `usage-trend-*.json`、对应 `.json.corrupt` 隔离副本及 `.lock` 文件清除历史，不要删除重置操作记录。

历史文件损坏时，应用会在同一文件锁内将坏文件隔离为 `.json.corrupt`，重新开始采样，并在趋势面板提示一次恢复状态。每个账号只保留最近一份隔离副本，副本不参与 8 天采样清理，可随历史一并删除；磁盘权限或读取错误不会触发这种恢复。趋势读写在后台串行执行，不阻塞前台刷新；账号切换、退出及后续刷新会使旧任务的界面更新失效。
